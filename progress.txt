# Google Sheets Backup Feature - Progress & Learnings

## Codebase Patterns

### Manual Testing Documentation - Data Type Testing
- **Baseline Recording Critical**: Record exact values BEFORE export for byte-by-byte comparison
- **Two-File Comparison Strategy**: Export baseline before export, export again after import, use `diff` for validation
- **Type Verification Queries**: Use `typeof()` function to verify SQLite type preservation (integer, real, text, null)
- **Comprehensive Type Coverage**: Test all 5 SQLite types: integer (booleans), real (floats), text (strings, timestamps), null, blob
- **Transformation Validation**: Verify reversibility of transformations (NULL↔empty, 0/1↔TRUE/FALSE)
- **Pass Criteria Precision**: No differences allowed in diff output (exact preservation required)

### Manual Testing Documentation
- **Location**: `docs/` directory for comprehensive testing guides
- **Format**: Markdown files named `manual-testing-[id].md` (e.g., manual-testing-mt002.md)
- **Content Structure**:
  - Test objective and background
  - Prerequisites checklist
  - Detailed step-by-step instructions
  - Expected outcomes (pass/fail criteria)
  - Common issues and troubleshooting solutions
  - References to implementation code
- **Purpose**: Provide clear, repeatable instructions for manual E2E testing with real APIs
- **Best Practice**: Include code references (file:line) to implementation details

## Previous Codebase Patterns

### Project Structure
- **Services:** `chibi/services/` - Business logic layer, inject dependencies via `__init__`
- **Database:** `chibi/database/` - Async SQLite with aiosqlite, repositories pattern
- **Cogs:** `chibi/cogs/` - Discord command handlers using discord.app_commands
- **Tools:** `chibi/tools/` - LangGraph tools, each has `tool.py` with Tool interface
- **Tests:** `tests/` - pytest with pytest-asyncio, mocks in `tests/mocks/`

### Async Patterns
- All service methods are async: `async def method_name(self) -> ReturnType:`
- Database operations use async context managers
- Discord command handlers are async
- Use `await` for all async calls
- pytest-asyncio mode is "auto" (see conftest.py)

### Database Patterns
- **Location**: `data/chibi.db` (SQLite database with student progress)
- **Schema Documentation**: See `DATABASE_STRUCTURE.md` for complete schema
- **Tables to backup**: users, quiz_attempts, concept_mastery, llm_quiz_attempts, attendance
- **Data Types**: BOOLEAN stored as 0/1, TIMESTAMP as ISO string, NULL as NULL
- Connection: `async with self.db.connection() as conn:`
- Transactions: `async with conn.execute("BEGIN"): ... await conn.commit()`
- Queries: `async with conn.execute(query, params) as cursor:`
- Schema defined in `chibi/database/connection.py` - see `_init_schema()` method
- Migrations: Adds review_status, student_id columns to existing databases
- Repositories inherit from BaseRepository
- Always use parameterized queries to prevent SQL injection
- For tests: Use `Database(":memory:")` for in-memory testing

### Service Patterns
- Located in `chibi/services/`
- Inject dependencies via `__init__(self, db: Database, config: Dict, ...)`
- Example: `QuizService(db, rag_service, llm_manager, config)`
- Return Dict or dataclass for structured data
- Raise custom exceptions, catch in cogs for user-friendly messages
- Add logging: `logger = logging.getLogger(__name__)`

### Discord Cog Patterns
- Located in `chibi/cogs/`
- Inherit from `commands.Cog`
- Use `@app_commands.command()` for slash commands
- Admin check: `@commands.has_permissions(administrator=True)`
- Ephemeral messages: `await interaction.response.defer(ephemeral=True)`
- Error handling: Catch exceptions, show user-friendly messages
- Registration: Add to `chibi/bot.py` in setup_hook or similar

### Testing Patterns
- Test files mirror source structure: `tests/test_[module].py`
- Fixtures in `conftest.py` - database, mock clients, etc.
- Mocks in `tests/mocks/` - Discord objects, LLM providers
- Use `@pytest.fixture` for reusable test setup
- Mark async tests with `@pytest.mark.asyncio` (auto mode)
- Use `@pytest.mark.skip` for tests before implementation
- Mock external APIs: `unittest.mock.patch()` or `unittest.mock.Mock()`
- In-memory database for tests: `Database(":memory:")`
- **Test Credentials**: `google-credentials.json` in project root for manual testing
  - Use ONLY for manual testing during development
  - Unit tests should ALWAYS mock Google API calls
  - Never use real production credentials in tests

### Configuration
- Main config: `config.yaml` - YAML format
- Structure: Top-level keys (bot, database, llm, similarity, backup)
- Access in code: `self.config.get('backup', {}).get('google_sheets', {})`
- Environment vars: Use `.env` for secrets (Discord token, API keys)
- Example section structure:
  ```yaml
  backup:
    google_sheets:
      enabled: true
      credentials_file: "credentials/google_oauth_credentials.json"
      token_file: "credentials/token.json"
  ```

### Git Patterns
- Branch naming: `ralph/[feature-name]`
- Commit message format: `[type]: [story-id] - [subject]`
- Types: feat, test, fix, chore, refactor, docs
- Always include: `Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>`
- Exclude from git: `credentials/*.json`, `data/`, `.env`

### Dependencies
- Package manager: `uv` (not pip)
- Install: `uv sync`
- Add dependency: Edit `pyproject.toml` then run `uv sync`
- Test imports: `python -c 'import package_name'`

### Running Tests
- All tests: `uv run pytest tests/ -v`
- Specific file: `uv run pytest tests/test_[component].py -v`
- With coverage: `uv run pytest tests/ --cov=chibi --cov-report=term-missing`
- Collect only (check structure): `uv run pytest tests/ --collect-only`

## 2026-01-11 - US-011
**What was implemented:** Google Sheets to SQLite importer with validation and transactions
**Files changed:**
- chibi/backup/sheets_importer.py (created - 411 lines)
- chibi/backup/__init__.py (updated - exported SheetsImporter, ValidationError, ImportError)
- tests/test_sheets_importer.py (updated - removed skip markers)

**Implementation Details:**
- **Schema Validation:** `_validate_schema()` checks for Metadata sheet, required data sheets, and schema version compatibility
- **URL Extraction:** `_extract_spreadsheet_id()` handles full URLs, short URLs, and plain IDs using regex pattern matching
- **Data Type Conversions:** `_convert_sheet_row_to_sqlite()` reverses exporter transformations
  - "" (empty string) → None (NULL)
  - "TRUE"/"FALSE" → 1/0 (boolean columns)
  - Numeric strings → int or float (based on column type)
  - Timestamps → preserved as ISO strings
- **Import Modes:**
  - Replace mode: DELETE FROM all tables, then INSERT new rows
  - Merge mode: INSERT OR REPLACE (updates existing by ID, inserts new)
- **Transaction Safety:**
  - All imports wrapped in BEGIN/COMMIT transaction
  - PRAGMA foreign_keys = ON to enforce referential integrity
  - Automatic ROLLBACK on any error
  - Foreign key violations caught and re-raised as ImportError
- **Table Import Order:** Users first, then child tables (respects foreign keys)

**Learnings:**
- **Foreign Key Enforcement:** SQLite doesn't enforce foreign keys by default - must run `PRAGMA foreign_keys = ON` before transaction
- **Transaction Pattern:** Enable foreign keys BEFORE BEGIN to ensure they're active in transaction
- **Error Handling:** Catch database exceptions during INSERT, log the row data, re-raise as ImportError for user-friendly messages
- **Type Conversion Maps:** Define column types per table (BOOLEAN_COLUMNS, INTEGER_COLUMNS, FLOAT_COLUMNS) for accurate conversion
- **URL Regex:** Pattern `/spreadsheets/d/([a-zA-Z0-9-_]+)` extracts ID from various Google Sheets URL formats
- **Empty Row Handling:** Skip rows where all values are empty strings to avoid inserting null rows
- **Row Padding:** Pad rows with empty strings if they're shorter than headers (handles incomplete data)

  - Use IS NULL queries, not equality checks (NULL != "")

  - Query: `SELECT column, typeof(column) FROM table WHERE column IS NULL;`
  - Empty string and NULL have different semantics in SQL

- **Timestamp Preservation:**
  - ISO format must match exactly: YYYY-MM-DD HH:MM:SS
  - No timezone conversion (timestamps stored as-is)
  - No format changes or precision loss
  - Stored as TEXT type (SQLite convention)
  - Compare character-by-character with baseline

- **Numeric Type Preservation:**
  - INTEGER columns: typeof() returns 'integer'
  - REAL columns: typeof() returns 'real' with decimal precision
  - No type coercion (int to float or vice versa)
  - Float precision preserved (Google Sheets has ~15 digits)
